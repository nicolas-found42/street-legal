## Event conversion fix

Original `425c60` interprets the full mask `0x00100000` as one VM object
argument. Otherwise the low 28 bits select integer only for kind `0x80`;
other supported kinds convert a native string before constructing GameRef.
The controlled original probe exercises 112 cases with source/null,
argument/null, async, explicit method name and high mask bits. Its fixtures
are regenerated by `re/oracle/script_event_arguments_probe.py` and compared
by `engine::event_argument_tests`. This probe supplies VM collaborators;
it does not establish complete native dispatch or stock-game reachability.

The production adapter now selects overload by event kind, rejects unconverted
nonzero native addresses before allocating VM objects, and converts a null
word to the appropriate integer zero or null string. The `47da30` queueEvent
wrapper accepts a String and converts it to a native C-string address. A
nonnull string sent with an integer/object mask therefore remains an explicit
identity boundary; its native address must not become an invented VM word.
Five focused engine tests pass, including the 112-case original comparison
and rejection-before-allocation checks. Native-created object identities and
physics structure arguments still require their own modeled conversions.

## Callback lifecycle recovery and integration

Original427370/4274e0 append intrusive callback nodes with weak references,
retain duplicate registrations and retire only the first matching ID. The node
remains on its list until traversal destroys it. Original426f60 snapshots the
next node immediately before the current callback, then reads later content
live; appending from an earlier callback can be visible in the same pass,
while appending from the final callback waits for the next pass. These facts
were recovered from the original with REA/Ghidra and verified by
`re/oracle/native_callbacks_probe.py`. The REA registration/retirement/drive
reads are preserved under the x87-research checkpoint as `frame-rea-*.json`.

The probe compares36 registration/removal sequences and eight mutation
scenarios over two actual original426f60 passes. Its declared per-resource
frame collaborator executes normal x86 CALLs to the real427370/4274e0 from
inside the traversal; the outer list loop and weak-reference code are not
substituted. The Rust test compares complete caller heaps, live callback
references and every deferred free. These44 cases pass. It does not establish
per-resource frame behavior or complete control/animation parity.

Production `native_callbacks.rs` replaces the callback resource-ID Vec.
Registration, retirement, resource invalidation and per-node traversal now
share native weak-reference storage; VM callbacks can mutate that live graph.
A separate production lifecycle regression destroys a resource, reuses its ID
and verifies that the old callback remains dead. Per-resource426e10 drive and
generic native control/animation dispatch stay explicit gaps.

## A concrete x87 implementation candidate

Bochs added a new standalone FSIN/FCOS model in September 2026. Its source
describes a 66-bit pi/2 reduction constant, separate polynomial/table paths,
asymmetric multiplication and intermediate 67-bit truncation / 64-bit nearest
rounding. It explicitly distinguishes standalone instructions from FSINCOS.
This supplies a concrete algorithm to investigate rather than a host libm
replacement. [Upstream implementation](https://github.com/bochs-emu/Bochs/blob/d245c751e6a6fab4bf68e72823598a48001adb3c/bochs/cpu/fpu/fsincos.cc),
[rounding helpers](https://github.com/bochs-emu/Bochs/blob/d245c751e6a6fab4bf68e72823598a48001adb3c/bochs/cpu/fpu/f128_67.cc),
[constants](https://github.com/bochs-emu/Bochs/blob/d245c751e6a6fab4bf68e72823598a48001adb3c/bochs/cpu/fpu/fsincos_constants.h).

`slr_x87::intel_trig::candidate_f32` adapts that value model in Rust, using
the existing vendored Berkeley SoftFloat binary128 primitives. Its supported
input contract is finite FLD m32 operands, nearest rounding and masked
exceptions; it does not model status flags or arbitrary extF80 inputs.
The adaptation and retained constants carry the upstream notice. The
independent upstream C++ harness stays under ignored `re/out`, outside Cargo.
The candidate is behind the disabled-by-default `experimental-intel-trig`
feature and is **not connected to production Euler construction**.

The first independent comparison at
`re/out/checkpoints/20261021-campaign/x87-research/comparison-1/`
compiled pinned upstream commit
`d245c751e6a6fab4bf68e72823598a48001adb3c` and compared all 9,815
finite input words: **zero Rust/upstream mismatches**. Inputs include signed
zero, denormals, exponent/table boundaries, the current failing angle,
out-of-range operands and seeded random words. This verifies the adaptation
against that implementation, not hardware or original-game parity.

## Disagreements are unresolved evidence

The original Euler capture contains 174 unique finite input words. Comparing
its six raw intermediates per case to the candidate produces 360 mismatching
observations. These have not been excluded or normalized. Unicorn 2.1.4's
primary source explains why raw results need investigation: `helper_fsin`
and `helper_fcos` narrow extF80 to host double, call host `sin`/`cos`, and
widen the result. Their range test uses strict greater-than against MAXTAN.
That is a different algorithm from the Intel microcode model, including at
the exact 2^63 boundary.
[Unicorn 2.1.4 implementation](https://github.com/unicorn-engine/unicorn/blob/2.1.4/qemu/target/i386/fpu_helper.c).

The streaming x86_64 probe `re/x87probe/rosetta/trig_stream.c` executes actual
FSIN and FCOS instructions under Rosetta 2 with CW `0x007f`, without a math
library. On the same 9,815 finite inputs, it disagrees with the candidate in
308 rows: eight below pi/4 and 300 in the remaining reduced range. All 1,195
rows between the tiny range and 1/4 agree, as do the 3,634 tiny and 2,510
out-of-range rows. Rosetta remains translated execution, not a physical Intel
CPU. These results do not justify promoting the candidate to a trusted
operation or relaxing G11. Full raw outputs are retained in `rosetta.txt`.

The full-consumer diagnostic preserves all original observations and fails
with **20 unsupported cases, 12 differing complete caller heaps and360 raw
intermediate differences**. All12 heap differences are the signed values just
below2^63 and exactly2^63; the ordinary finite-angle/mixed cases compare equal
at the memory boundary. This does not erase their raw-value disagreements or
promote the operation's trust. Retained report:
`re/out/boot/intel-euler-candidate-1792645387492746000.json`.
The experimental diagnostic is deliberately red while any observation is
unsupported or unequal. It is separate from the unchanged production-domain
checks and supplies no acceptance credit. Reproduce it with:

```sh
cargo test -p slr-boot --bin slr-boot --features experimental-intel-trig intel_euler_candidate_complete_consumer_diagnostic -- --nocapture
```

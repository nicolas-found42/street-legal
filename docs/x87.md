# x87 probe results (M0-07)

Ticket: issue #8 (plan id M0-07). Branch `m0-07-x87-probe` contains the
`exact-port` tip (`f98615f`; verified via `merge-base`).
Probe suite: `re/x87probe/` (tracked). Regeneration: `re/x87probe/README.md`.
No vectors are committed: the corpus, raw oracle outputs and the referee
tables live under `re/out/x87/` (git-ignored). Vector IDs below refer to
`corpus.jsonl` row numbers so any local regeneration reproduces them.

Semantic reference throughout: Intel SDM Volume 1 section 8.1.5.2
(precision control) and Volume 2 (`FPREM` exact-result / RC ignored,
`FIST`/`FISTP` RC-honored, comparisons unaffected by RC).

## Oracles that actually ran

1. **Berkeley SoftFloat, Release 3e** (`ucb-bar/berkeley-softfloat-3`,
   `8086-SSE` specialize, stock `build/Linux-x86_64-GCC` Makefile driven by
   the system `gcc` = Apple clang 21.0.0 on arm64 macOS). `extF80` add/sub/
   mul/div/sqrt/rem, `extF80_to_i32`, quiet/signaling compares. Tininess
   detection: `softfloat_tininess_beforeRounding` (x87 choice).
2. **Unicorn 2.1.4** (shared venv `~/slr-oracle-venv`). Fresh 32-bit instance
   per vector: FPCW set from the vector's (PC, RC), operands loaded as exact
   80-bit images via `FLD tbyte`, one instruction stub, ST(0)/memory/flags
   read back exactly. Final stub forms (after three fixed harness bugs —
   wrong `FSUB`/`FDIV` direction forms, `FSTP`-instead-of-`FST`,
   `FISTTP`-instead-of-`FISTP m64`, ST1/ST0 misread): `FADD ST0,ST1` D8 C1,
   `FSUBR ST0,ST1` D8 E9 (= a−b), `FMUL ST0,ST1` D8 C9, `FDIVR ST0,ST1`
   D8 F9 (= a/b), `FST m64` DD 15, `FISTP m32` DB 1D / `FISTP m64` DF 3D.
3. **mpmath 1.4.1 tiebreaker** (transcendentals only, 200-bit precision,
   correctly rounded to 80-bit per RC). Not a ticket oracle; resolves
   Unicorn-vs-SDM questions where SoftFloat has no coverage. Out-of-domain
   inputs (`|x|>1` for `F2XM1`, extreme `FYL2X` magnitudes) are excluded from
   comparison rather than fed to `power()`.

**Precision-control emulation (a finding in itself):** SoftFloat always
rounds the 64-bit significand unless `extF80_roundingPrecision` is set to
32/64. The harness maps PC 24/53/64 to precision 32/64/80 for
`fadd/fsub/fmul/fdiv/fsqrt` only (`"pc_applied": true); every other op runs
at precision 80 (`"pc_applied": false). This matches the SDM exactly: PC
shortens only the significand (low bits zeroed, verified on tie vectors);
the exponent keeps its full 15-bit range. `slr-x87` (M0-14) should copy
this wrapper strategy.

**Corpus:** 21,702 deterministic vectors (`sha256 c9616f79…156edd`),
per-op: fadd/fsub/fmul 2940, fdiv 3084, fsqrt 828, fsin/fcos 350,
f2xm1 85, fyl2x 425, fpatan 255, fprem 70, fcom/fcomp/fucom/fucomi 1625,
fld/fst 325, fistp 285. Classes: small ints, f32-exact/inexact, denormals
(f32/f64/ext subnormals, pseudo-denormal, unnormal), huge/tiny exponents
(up to ext-max and below ext-min-normal), pi/2 neighborhoods (incl. 1e8–1e19
magnitudes), log-domain edges, fprem reduction cases, NaN/±0/±inf, and
double-rounding boundary pairs. Basic ops run all 12 PC×RC cells;
PC-independent ops run 4 RC cells at PC=64 plus a PC=24 witness.

**Referee rules** (`compare.py`): register results compared bit-for-bit
(sign + biased exponent + significand), except NaN payloads are
payload-insensitive (SNaN-vs-QNaN class differences still fail); fistp
compares i32/i64 values; compares compare C-bits; fprem compares remainder
plus C2. Totals: **17,429 agree / 3,978 mismatch** of 21,702 (plus special/NaN buckets; see `results.json`).

## Trusted-operation table

Legend per cell: `S` SoftFloat agrees-or-justified, `U` Unicorn agrees,
`s`/`u` oracle not applicable there by construction (U ignores PC;
S has no transcendentals). Verdict **TRUSTED** means cleared for bit-exact
use in `slr-x87`; **APPROX** means cleared only with a tolerance;
**UNTRUSTED** means do not use.

| fadd | S agrees (U differs: ignores PC) | S agrees (U differs) | S=U agree | **TRUSTED** (S at 24/53, both at 64) |
| fsub | same pattern | same pattern | S=U agree | **TRUSTED** |

| fsqrt | same pattern | same pattern | S=U agree | **TRUSTED** |

Mismatch composition (all RC): at PC24/PC53 the bulk is the Unicorn-PC gap
(proven: Unicorn returns bit-identical results across PC for the same
vector/RC, e.g. fmul tie vector identical at PC 24/53/64). At PC64 only the
invalid-operand class remains: unnormal inputs (e.g. id 1940: Unicorn NaN
vs SoftFloat finite) and signed-zero edges (e.g. fmul id 8468: −0×1 →
SoftFloat −0, Unicorn +0; fdiv zero/inf-sign cases ids 11840–11900).
Game relevance: none — game floats enter via `FLD m32/m64`/`FILD`, which
never produce unnormals, and game code does not depend on ±0 sign identity
(verified: no other zero-sign divergence in 21,702 vectors).

At the **game config (PC=24, RC=0)** all five ops are TRUSTED via the
SoftFloat leg, including directed-rounding cells and the double-rounding
boundary pairs (PC24 register results come back with low significand bits
zeroed, e.g. fadd id 0 → `0x8000…0000`, so a later `FST m32` cannot double-
round — the M0-14 wrapper gets this property for free).

only — x87 exception-flag parity is NOT covered by the Unicorn leg).

## Edge-case findings (ticket scope items)

- **Denormals:** ext subnormals and f32/f64 subnormals behave sanely on both
  oracles for arithmetic; pseudo-denormal and unnormal encodings are the
  both-oracles-diverge zone (see tables). Game-irrelevant (no producer).
- **Exponent range beyond f32:** full 15-bit register range confirmed on
  both oracles — no f32-range clamping before an explicit `FST m32`
  (vectors at exp 128/1023/1000/10000/16382 all agree at PC64).
- **Double rounding:** eliminated at PC=24 by the significand-rounding
  itself (boundary-pair vectors agree SoftFloat-side at PC24 in every RC);
  Unicorn cannot confirm (ignores PC) — documented, not hidden.
- **NaN payloads:** oracles differ in propagation payload; comparison is
  payload-insensitive by design; SNaN-vs-QNaN class tracked and agreed on
  all non-unnormal vectors. The game never branches on payload bits.

## Rosetta leg (M0-09, third oracle)

Runner: `re/x87probe/rosetta/probe.c` (win32 console, mingw-w64 i686 GCC
16.2.0), executed under Wine 11.0 (Gcenx `11.0_1`, Rosetta 2 on arm64 macOS
26.6, Apple M5 Pro). Same 21,702-vector corpus (`c9616f79…156edd` — the
worktree regenerated `corpus.jsonl` byte-identical per `gen_vectors.py`;
manifest sha verified at generation), same per-op stubs and load orders as
`run_unicorn.py`, fresh `FNINIT`+`FLDCW(pc,rc)` per row. Referee:
`re/x87probe/compare_rosetta.py` (same NaN-tolerant rules as `compare.py`;
transcendentals vs mpmath 200-bit). Raw tables: `re/out/x87/rosetta_results.json`
+ `rosetta_disagreements.json` (git-ignored). Result: **agree=17,651 /
mismatch=3,756 of 21,702** (run: `wine C:\probe.exe`, 21,702 rows, EXIT=0,
~1.5 s; logs in `re/out/wine/logs/probe-stdout.log`).

Headline: Rosetta **honors PC+RC exactly** (PC24 rounds the significand to 24
bits, PC53 to 53, PC64 exact — verified on double-rounding boundary pairs, e.g.
corpus id 0: PC24→`0x8000000000000000`, PC53/64→`0x8000004000000000` matching
SoftFloat bit-for-bit). Every residual mismatch is in the already-documented
invalid-operand / −0 / NaN-flag corners:

Game-config verdict (PC=24, RC=0): the Rosetta leg **corroborates every M0-07
TRUSTED verdict and changes none** — all mismatches are unreachable via

game does not branch on. Two probe-harness bugs found and fixed on the way

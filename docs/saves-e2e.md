# Saves/config end to end (G9 / S8)

Contract: `docs/fidelity.md` tier E — the same scripted session yields
byte-identical original SDAT save/config files; port saves load in the original
and original saves load in the port. Obligations: **S8** (native-level, runnable
today) and **G9** (script-level, blocked). Feeds P02 (options) and P03 (career).

## What runs now (S8)

The `File` natives are the only code that touches SDAT bytes: `open` writes the
8-byte header and (read mode) scans the footer, `write(int|float|String|
ResourceRef)` append the body, `close` writes the version-2 footer, and
`readInt|readFloat|readString|readResID` load it back. `Config.saveConfig`,
`ControlSet.save` and `Vehicle.save` are sequences of exactly those calls
(docs/formats.md SDAT). `re/oracle/save_sessions.json` scripts such sequences
(options, controls, vehicle with saved and script-side resource references,
float/string edge values, two files open at once, closed/unopened/invalid-mode
arms) plus read-back sessions and reads of the stock options and the eight stock
vehicle saves.

| Side | Runner | What executes |
|---|---|---|
| original | `re/oracle/save_session.py run` | the real build-606 natives and the real footer scan (`0x485190`, `0x485655`) in one persistent Unicorn world |
| port | `cargo run -p slr-io --example save_session` | `FileHost` over a scratch root |

The original's boundary replacements are listed in `save_session.py`'s docstring
(file layer, object fields, resource-manager lookups, texture loaders, allocator,
interner, log sink); the file layer's own path conversion and CRT slot table are
covered by `filelayer_vectors.py`. The comparison covers every operation's
result, the native struct, the rebuilt resource/slot tables, the companion/blob
load requests, the log, every file's bytes, and cross-loading: the original reads
the files the port wrote and the port reads the files the original wrote
(`acceptance/saves.py`).

```sh
sh acceptance/run.sh --execute S8 --json      # fresh runs, retained bundle, verdict
python3 acceptance/selftest.py                # data-free adversarial self-tests
```

`--execute S8` builds the port runner in an isolated target directory, freezes
source/stock/executable identity, runs the four sessions (original, port,
original reading the port's files, port reading the original's files), recomputes
file hashes from disk, and fails closed on any difference, dropped operation,
other spec/executable, malformed SDAT or empty read. It needs the oracle venv
(`~/slr-oracle-venv`, or `SLR_ORACLE_PYTHON`).

### Findings fixed by this work

- `File.open` (read mode) did not rebuild the resource table or the slot run,
  and read the slot-count and resource-count words back to back although the
  slot run sits between them. A save with JPEG slots therefore loaded with a wrong
  resource count and no rows, so `readResID` after a reopen missed where the
  original hits (original vehicle saves could not cross-load). `slr-io` now walks
  `[slot count][slot triples][resource count][entries]` like the exe; a loaded
  slot row carries `res_id` 0, matching the original.

### Fixture provenance and regeneration

No original-derived bytes are committed. `save_sessions.json` is authored data:

```sh
python3 re/oracle/save_session_spec.py            # regenerate the spec
python3 re/oracle/save_session_spec.py --check    # exit 1 if the checked-in file is stale
```

The original-produced files (`<run>/original/files/<session>/<name>`) are run
products of `save_session.py` over `reference/raw/StreetLegal_Redline.bak.exe`
(sha256 `7d77466a8c1a34d16a59d9ccf2e8059664dff1bfb421338074a461a932e8edde`) and
are regenerated by each `--execute S8` run; retained runs live under
`re/out/acceptance/saves-*` and are archived with a manifest under
`~/Documents/street-legal-evidence/saves-s8-<UTC timestamp>/`. Nothing is
regenerated in place: every run writes a fresh directory.

### Known limits (documented, not hidden)

- Signalling-NaN floats are compared as raw words (the bytes), not through
  `readFloat`: x87 `FLD` quiets them on hardware and Unicorn's FPU does not.
- A footer whose counts exceed the file is the exe's undefined end-of-file loop;
  the sessions never feed one.
- Companion/texture objects are renderer-side; the port records the loader
  requests (`FileHost::loads`) and the comparison checks those.

## What is blocked (G9)

1. **Script-level sessions.** G9 asks for the same scripted session through the
   original scripts: `Config.saveConfig`, `ControlSet.save`, `Vehicle.save` and
   the career save/load flow. The stock scripts run only when the native-VM
   replay frontier (`crates/slr-boot`, `crates/slr-vm`) boots them to a state
   where those methods can be called. When it does, the same
   `results.json` schema applies: run the scripted session in the original
   (oracle) and in the port, feed the files across, and extend
   `acceptance/saves.py` to require that evidence.
2. **JPEG companion bytes.** Vehicle saves carry `<save>.<n>` JPEGs produced by
   the script-side screenshot/texture natives and the original's JPEG encoder
   over a rendered surface (`0x48daa0` / `0x48da30` save a slot node's
   attached object; `File.write(ResourceRef)` nodes carry none). The port has no
   producer until the render frontier (D3D9, M5) exists, so companion bytes
   cannot be compared yet.

`acceptance/saves.py` therefore reports G9 as `blocked`, never `passed`, even
when S8 passes.
